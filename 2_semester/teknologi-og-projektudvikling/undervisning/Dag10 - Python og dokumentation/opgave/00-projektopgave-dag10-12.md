# Projektopgave Dag 10-12: Siemens PLC, Emulate3D og Python

Denne projektopgave starter paa Dag 10, fortsaetter paa Dag 11 og afsluttes paa Dag 12.

I arbejder i grupper af 3 personer og udvikler en prototype, hvor Siemens PLC, Emulate3D og Python indgaar i samme loesning. Dokumentationen maa gerne ligne dokumentet Eksempel: Vandstandsstyring med PLC og Python, men det er jer selv, der skal definere jeres loesning og bruge V-modellen som arbejdsmetode.

## Formål

Projektet skal vise, at I kan gaa fra ide til faerdig prototype og skabe sammenhaeng mellem krav, design, implementering og test.

## Opgavens faste rammer

Foelgende skal indgaa i projektet:

- en gruppe paa 3 personer
- en Siemens PLC, fysisk eller simuleret
- Emulate3D som en reel del af loesningen
- Python som aktiv softwaredel
- mindst et nyt element ud over basisloesningen
- aflevering og demo paa Dag 12

## Det I selv vaelger

I vaelger selv scenarie, proces, signaler og systemopbygning, saa laenge loesningen giver faglig mening. I vaelger ogsaa selv, om PLC'en er fysisk eller simuleret, og hvordan Python skal skabe vaerdi i systemet.

## Dokumentation og arbejdsform

I skal selv bruge V-modellen som arbejdsmetode, saa der er tydelig sammenhaeng mellem ide, krav, design, implementering og test.

Jeres dokumentation skal som minimum indeholde:

- kort systembeskrivelse
- kravspecifikation med acceptkriterier
- blokdiagram
- flowchart eller state machine for Python-delen
- beskrivelse af samspillet mellem PLC, Emulate3D og Python
- testoversigt med resultater
- kort afsluttende vurdering eller konklusion

## Det ekstra element

Projektet skal udvides med mindst et nyt element, som kan forklares og demonstreres tydeligt. Det kan for eksempel vaere:

- ekstern kommunikation med en anden gruppe
- brug af et API
- en Flask-server
- et HMI i Python
- en webbaseret statusvisning
- en anden loesning godkendt af underviseren

Det nye element skal give reel vaerdi i systemet og ikke kun vaere pynt.

## Arbejde fordelt paa dagene

| Dag | Fokus | Det I skal have lavet |
| :-- | :-- | :-- |
| Dag 10 | Projektstart og plan | Gruppedannelse, scenarie, foerste version af kravspecifikation og acceptkriterier, blokdiagram, flowchart eller state machine, valg af nyt element |
| Dag 11 | Implementering og integration | PLC-kommunikation, kobling til Emulate3D, Python-logik, logning og foerste fungerende version af det nye element |
| Dag 12 | Test, dokumentation og aflevering | Faerdig loesning, test mod egne krav, samlet dokumentation, demo og aflevering |

## Leverancer

Ved slutningen af Dag 10 skal I have:

- skrevet gruppemedlemmer ind
- valgt scenarie og systemformaal
- lavet foerste version af kravspecifikation og acceptkriterier
- lavet blokdiagram
- lavet flowchart eller state machine
- beskrevet det nye element

Ved slutningen af Dag 11 skal I have:

- etableret PLC-kommunikation i Python
- koblet loesningen sammen med Emulate3D
- lavet logning til fil
- lavet foerste fungerende version af det nye element
- noteret hvad der mangler foer Dag 12

Ved slutningen af Dag 12 skal I have:

- en faerdig prototype
- testet jeres krav og skrevet resultaterne ind
- samlet dokumentationen i repoet
- dokumenteret det nye element
- gennemfoert en kort demo

## Det der skal afleveres

Repoet skal som minimum indeholde:

- kort projektbeskrivelse
- kravspecifikation med acceptkriterier
- blokdiagram
- flowchart eller state machine
- beskrivelse af PLC-signaler, tags eller dataudveksling
- Python-kode
- screenshots eller billeder fra Emulate3D, HMI eller test
- logfil eller CSV-eksempel
- testoversigt
- kort beskrivelse af det nye element

## Vurdering

Der laegges vaegt paa:

- at PLC, Emulate3D og Python spiller sammen
- at der er tydelig sammenhaeng mellem krav, design, implementering og test
- at gruppen kan forklare deres loesning og demonstrere den paa Dag 12
- at dokumentationen er overskuelig og passer til det system, der faktisk er bygget
- at det nye element virker og giver mening

Projektet afsluttes paa Dag 12.
